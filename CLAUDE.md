## Project status

Next.js 16 (App Router) + Tailwind v4 + shadcn/ui (Radix) + Lucide, scaffolded at the repo root. [SPEC.md](SPEC.md) is the build plan; [decisions.md](decisions.md) logs every design/implementation decision (`decision - because reason`) and must be appended to when a new one is made.

- Design tokens live in `app/globals.css` `@theme` (Tailwind v4, no `tailwind.config.js`). Default Tailwind palettes are reset, so only design.md values exist as utilities. Custom font-size/radius/shadow names are registered in `lib/utils.ts` (`extendTailwindMerge`) — add new token names there too or `cn()` will silently drop classes.
- Figma draws strokes inside the box: use `ring-1 ring-inset` (or an overlay), never `border`, or elements grow by 2px and the layout drifts. Line heights are explicit per `text-*` token in `globals.css` (Figma's rounded Inter "normal", not Chrome's).
- `References/` holds Figma PNG exports (2× desktop 1440×850, 3× mobile 390×844) to compare against; `comparison/` holds the latest before/after boards.
- All mock data lives in `lib/mock-data.ts`.
- shadcn components in `components/ui/` are restyled to the tokens; the CLI generates shadcn default color names (`bg-background`, etc.) that don't exist here, so re-map them after every `npx shadcn add`.

## What this project is

A clickable, responsive prototype of a "Projet" (Project) feature for CompagnyChatGPT — an internal, on-premise, ChatGPT-like conversational assistant with ~30,000 monthly active users. The "Projet" feature is a personal knowledge space: users store documents that the assistant uses to enrich its answers, and can run project-scoped chats.

The prototype must cover three user journeys, clickable end-to-end, responsive (mobile + desktop):
1. **Gérer un projet** — create / edit / delete / pin / unpin a project
2. **Gérer les sources d'un projet** — add, preview, and delete source files within a project
3. **Travailler dans un projet** — chat within a project, pin/delete chats, view a cited source from within a chat

Full page inventory and step-by-step click flows (desktop + mobile, with Figma node links) are in [build-context.md](build-context.md), sections 7–8.

## Tech stack (per build-context.md §4, to be used once scaffolded)

- Next.js + Tailwind, deployed on Vercel
- Icons: **Lucide react only** — never use icons exported from the Figma mockups
- `tailwind.config.js` must be driven entirely by the tokens in `design.md`
- Components built from **Radix** (behavior) + **shadcn/ui** (components), customized to visually match the Figma file referenced in build-context.md
- Figma source: linked in build-context.md §4/§7 (design + prototype flows, node-id links per screen)

## Design constraints (per build-context.md §5)

- Interface must be fully responsive: mobile and desktop
- Must meet **WCAG AA** accessibility
- Styling must use **only** values defined in `design.md` — never invent hex/arbitrary values
- Component data must be mocked in dedicated data files (e.g., a "Projet" data file, a "DataGrid Cell" data file) rather than hardcoded inline
