# Decisions

Format: decision - because reason.

- Tailwind v4 with tokens in `app/globals.css` `@theme` instead of `tailwind.config.js` - because it's the current Next.js/shadcn default; approved by the user, deviates from build-context.md §4 wording.
- Default Tailwind color, radius, font-size and shadow scales are reset (`--*: initial`) - because it makes off-system values unavailable, enforcing "never invent a hex" from build-context.md §5.
- Color tokens named `heading` / `ink` / `muted` rather than `title` / `text` - because `text-text` and `text-body` would be ambiguous between color and font-size utilities.
- App scaffolded at the repo root, no git repo initialized - because the user chose root placement and didn't ask for version control.
- Onest used for the Home greeting and suggested-prompt titles - because the Home Figma frames bind them to `--title_txt` (Onest), resolving the Onest-scope gap in design.md.
- `General Sans Variable` (seen once, on the mobile "Ma bibliothèque de prompts" label) replaced by Inter - because it appears nowhere else and isn't in design.md's type scale.
- Sidebar background uses the glass surface `rgba(255,255,255,0.5)` - because the Figma variable resolves to white in code, but every rendered frame shows the page wash through the sidebar.
- Page background served as two raster images via `<picture>` + `getImageProps` - because it's an image asset, not a token (design.md), and the desktop PNG is 3.6MB unoptimized.
- Drawer scrim is design.md's `Black` primitive at 40% opacity - because the Figma nav-overlay frame defines no scrim value; to be revisited against the dialog frames.
- Non-Projet chrome (search, collapse, Bibliothèque, Discussions, Épinglés, account menu, composer buttons, suggestions) is rendered `aria-hidden` / non-focusable rather than as dead buttons - because SPEC.md makes it inert, and focusable controls that do nothing mislead keyboard and screen-reader users.
- Home composer textarea is typeable but sends nothing - because SPEC.md §2 keeps Home's composer non-functional.
- Composer focus shown with a neutral `focus-within` ring - because Figma defines no focus style for the composer and WCAG 2.4.7 requires a visible one.
- AppShell moved into the root layout - because the sidebar's open/closed state must survive navigation between routes.
- Desktop sidebar collapses to a 76px rail (Figma "Home - Nav (close) - Desktop") with a 300ms width transition, disabled under `prefers-reduced-motion` - because Figma shows the two end states but no motion spec.
- The collapsed rail shows only Rechercher / + / Bibliothèque, with no "Projets" shortcut - because that's what the Figma rail contains; reaching Projets requires reopening the sidebar.
- Sidebar open/closed state is not persisted across page reloads (defaults to open) - because SPEC.md's localStorage persistence covers demo data, not UI chrome.
- Focus moves to the counterpart toggle after open/close - because the clicked button unmounts, which would otherwise drop keyboard focus to the page body.
- "Épinglés" and "Discussions" headers are collapsible on both desktop sidebar and mobile drawer (Radix Collapsible, open by default, chevron rotates ↑/↓) - because the user asked for it on mobile first (Figma "Nav" accordions closed), then asked desktop to behave the same; this overrides SPEC.md §1's "inert" rule for these two headers, while the discussion items themselves stay inert.
- Liste des projets title is "Projets" on mobile too - because the mobile Figma frame says "Projet" (singular) while desktop says "Projets"; treated as a typo.
- Project dates follow the desktop frame (3 août, 20 août for POC Salesforce) - because the mobile frame's "03 août" / "05 avril" contradict it and SPEC.md §4 lists the desktop values.
- Project dates are stored as ISO and shown as "Aujourd’hui" or "d mois" in Europe/Paris - because newly created projects must read "Aujourd’hui" like the seeded one, and a fixed time zone keeps server and client renders identical.
- Projects live in a `useSyncExternalStore` store over localStorage (`ccg:projects:v1`), seeded from `lib/mock-data.ts` - because SPEC.md §5 requires persistence across refresh; the server snapshot is the seed, so there's no hydration mismatch.
- Pinned projects are NOT reordered to the front of the grid - corrected from an earlier unconfirmed guess; the "Liste Projets - Projet Epinglé"/"Désépingler" Figma frames (nodes 3434:10868, 3434:13344) show the exact same card positions before and after pinning "Projet Secured", only a persistent pin badge is added next to "⋮". The grid stays in `seedProjects` order.
- Whole project card is clickable via a stretched title link, with the "⋮" button layered above it - because a button can't be nested inside a link, and this keeps one tab stop per action.
- Project card hover = solid white surface, orange border, hover shadow - because that's the Figma "Projet" component's Hover state (design.md); keyboard focus reuses the accent ring.
- Mobile project cards hide the description - because the mobile Figma frame shows only title + date.
- Zero-projects empty state: folder icon, "Aucun projet pour le moment" and a one-line explanation in a glass card, with the "+ Projet" button still in the header - because SPEC.md §3 requires it but no Figma frame exists; built only from existing tokens.
- Button and IconButton are shadcn-style (cva) components with the Figma "Bouton" variants (primary/secondary × lg/sm, plus a `responsive` size) - because build-context.md requires shadcn/ui components customized to the Figma library.
- Line heights are explicit per font-size token (12→15px, 14→17, 16→19, 24→29, 28→34, 32→39, 40→48, 52→63) and body is 19px - because Figma renders Inter's "normal" as 1.21× rounded, while Chrome rounds ascent and descent separately and gave 20px at 16px, which made every card 3px taller.
- Figma strokes are inside the box, so borders on buttons, cards and the profile chip are inset rings (`ring-1 ring-inset`), never CSS `border` - because a CSS border added 2px to every card, button and avatar (cards 165 vs 160px, button 42 vs 39px, avatar 42 vs 40px) and shifted the whole page.
- The mobile avatar ring is an overlay above the photo instead of a ring - because Figma draws the stroke over the image, which makes the visible photo 38px.
- Avatar photo is cropped like the Figma frame (133.3% height, top -1.19%) - because `object-cover` showed a slightly different framing of the face.
- Mobile header is sticky and turns solid white with a 1px bottom rule once the page scrolls - because the "Liste Projets - Scroll - Mobile" reference shows it; the rule is an inset shadow so the header stays 64px tall.
- A pin button appears next to "⋮" on card hover or focus-within, and is hidden (display:none) otherwise - because the Figma "Projet / Hover" component shows it. It is inert for now, like "⋮", until the pin and menu frames are built.
- Lucide plus is scaled 1.4× and chevrons 1.25× (transform, no layout impact); search is 17px and the sidebar toggle 19px - because Figma's glyphs fill ~90% of their 16px box while Lucide's fill 58%, measured against the reference PNGs (plus 14px, chevron 12×6.5px, search 14px, toggle 16px).
- Card descriptions get `-mr-1` - because Figma lets the ellipsis overhang the text box by ~1px, so it shows "printing and…" where Chrome cut at "printing an…".
- NOT matched, content conflicts between the references: mobile title reads "Projet" (desktop "Projets"), and mobile dates read "03 août" / "05 avril" (desktop "3 août" / "20 août" for POC Salesforce). One dataset can't satisfy both; desktop values and "Projets" kept, pending the user's call.
- NOT matched, renderer differences: Figma cuts long titles at a word boundary ("revente…") while Chrome cuts at the character ("revente …"); Figma gives some cards a fixed 440px width (right column ends 2px further right) instead of the grid's 438px; Lucide's hamburger has wider bar spacing (10.7px vs 8px tall) and its library/chat/folder glyphs differ slightly in shape from Figma's - build-context.md requires Lucide.
- Projet screen = `/projects/[id]` (Chats tab) and `/projects/[id]/sources`, sharing a layout (title, composer, tabs) - because SPEC.md §2 defines both routes and keeping the frame in a layout avoids re-rendering it on tab switch.
- Project title shows the stored name "Dashboard de suivi de projet", not the Figma frames' "Dasboard" - because it's a typo in the Figma copy and the name must match the card clicked in the list.
- Projet tabs: the active tab's 2px underline and the list's 1px rule are real CSS borders, and the inactive tab has no border (1px lower once centered) - because measuring the reference showed these Figma strokes add to the height, unlike cards and buttons; inset versions put everything below 3px too high.
- The chat table keeps Figma's empty 16px middle column - because it narrows titles so mobile truncation matches the reference ("implémenter…").
- Project composer placeholder is "Message Secured ChatGPT" on desktop and "Que puis-je pour vous aujourd’hui ?" on mobile, rendered as text hidden once the field has content - because Figma uses different copy per viewport and a native placeholder can't be responsive.
- Project composer radius 30px added as the `--radius-prompt` token - because it's a raw Figma value not in design.md's scale, and tokens are the only allowed styling values.
- Mobile project composer is sticky at the bottom of the viewport, after the list; on desktop it sits under the title - because that's where both Figma frames place it.
- Composer, row "⋮", title "⋮" and "+ Source" are inert on this screen - because sending (Lancer un chat), context menus, and the upload dialog are separate screens in SPEC.md, not built yet.
- Source thumbnails (Excel, PDF, Word, JSON, Gartner image) are the Figma image assets in `public/images/files/` - because they're file-type pictures, not UI icons (Lucide still covers every UI icon); `.md` reuses the JSON thumbnail like Figma does.
- Sources seed has 6 files, matching the reference - SPEC.md §4 lists a 7th (`1.2_AI_Fluency_Summary_16x9.pdf`) for the chat citation; it will be added when the "Lancer un chat" screen is built so this screen still matches its reference.
- Chats and sources persist in localStorage like projects, via a shared `createPersistentStore` factory - because SPEC.md §5 requires it for pin/delete/upload later; the projects store keeps the same API.
- Unknown project id shows "Projet introuvable" + a link back, only after hydration - because demo-created projects exist only in localStorage, so the server can't know whether an id is real.
- Zero-chats state: chat icon + "Vous n’avez pas de chat pour ce projet" - because SPEC.md §3 and the Figma "Copenhague" frames show it. Zero-sources shows only the "+ Source" button (out of scope in SPEC.md §3).
- NOT matched on the Projet screen: Figma truncates at word boundaries ("user…", "Openrouter…", "LLM 2…") where Chrome cuts at a character; Lucide's library/mic glyphs differ in shape; row text sits ≤1px lower (sub-pixel text positioning).
- "Lancer un chat" is a client-side state of the existing Chats tab (`/projects/[id]`), not a new route - because the only chat in this screen is SPEC.md's one scripted exchange (not one of the 6 pre-seeded chats, which have no transcript content), and its own sidebar in Figma shows it as a freshly-created "Discussions" entry, matching "sending a message" rather than "opening a saved chat." A dedicated `ChatSessionProvider` (in-memory, not localStorage) holds the active exchange; SPEC.md's chat-list persistence is untouched.
- Sending is wired only on the Chats tab; Sources keeps its composer purely decorative - because SPEC.md never asked for the Sources composer to do anything, and the skill says not to touch a screen I wasn't asked to build.
- Any prompt besides the exact scripted one gets a generic invented reply ("Je n'ai pas d'information supplémentaire…") - because SPEC.md §4 requires this fallback but doesn't specify wording; kept short and in an already-used color/type token only.
- Figma hides the project title, "⋮" menu and tabs once a conversation starts (confirmed in both Figma frames: neither node tree contains them) - implemented as conditional rendering, not CSS-hide, so the removed content doesn't take keyboard-tab or screen-reader time.
- The composer is physically repositioned by mode instead of CSS `order` tricks after `order-first` was found to place it *before* the title on desktop (it only meant to jump above the tabs) - regression caught by re-diffing the previously-built list screens after this change, fixed by rendering the composer in one of two literal JSX positions depending on `chatMode`.
- The sticky mobile composer is disabled specifically in chat mode (plain `static`) - because content here uses normal page flow, not a nested scroll region, and a sticky bar floats over flowing content it doesn't reserve space for; confirmed by reproducing real text-behind-composer overlap and fixing it this way, not by padding hacks.
- A second citation file, "1.5_Description_Summary.pdf", is added to seedSources alongside the one SPEC.md already flagged - because this screen's Figma frames show TWO citation badges, not one. The exact filename conflicts between Figma frames ("1.5_…" desktop vs "11.5_…" mobile, and mobile's answer text opens with a stray "BDans le 4D Framework…"); both look like Figma typos, resolved to the desktop spelling and the correct wording.
- Citation badges are real `<button>`s with no handler (Paperclip icon, Figma's "Badge — Filled") - because the file-preview dialog is a later screen; consistent with every other not-yet-built trigger in the app (real, focusable, inert).
- Reaction icons (Copy/RotateCcw/Volume2) are `aria-hidden`, non-interactive decoration - matches SPEC.md §1 exactly ("Reactions… rendered, not wired to any handler").
- AI avatar is a tight crop of the Figma "logo SCGPT_FD_FONCE" asset (the brand mark without its wordmark or dark backing circle) over a blurred white/50% circle - the closest asset available; not identical pixel-for-pixel to Figma's avatar treatment but same visual language as the header logo.
- Avatar hidden below `lg` - because the mobile Figma frame's "Prompt Envoi" has no avatar node; the desktop one does.
- Loading state: three bouncing dots inside an otherwise-identical answer bubble (`prefers-reduced-motion` disables the animation) - SPEC.md §3 requires exactly one loading indicator in the whole prototype and specifies only its rough duration (800–1500ms), not its look; built from existing tokens, no new ones.
- On sending, the page scrolls to top - a conversation can start while scrolled deep into a long chat list; nothing else resets the viewport for a visually shorter transcript.
- Character counters are real and computed (`value.length/max`), not copied from Figma - because Figma's own counters contradict themselves: the name field shows "10/15" under 19-character "Voyage à Copenhague" on *both* frames, and the description counter reads "0/350" on desktop vs "82/350" on mobile for the *identical* filled text. Neither is a real limit. Max lengths chosen fresh: 60 for name (comfortably fits the 43-character seeded "Site e-commerce…"), 350 for description (matches the one internally-consistent number, mobile's correct count of the shared example text).
- "Créer un projet" is a new `components/ui/dialog.tsx` (Radix Dialog, styled like the existing `sheet.tsx`) wrapping a form - the form fields are plain `<input>`/`<textarea>` rather than a new shared component, since this is their first real (non-decorative) use anywhere in the app and no second dialog needs them yet; extract if "Modifier un projet" repeats this shape.
- The dialog's overlay is `bg-black/50`, and the mobile nav drawer's `Sheet` overlay was updated from `/40` to match - the Create-project frames are the first to state the scrim's real opacity; a decisions.md note from the drawer build had flagged this exact value as unconfirmed and pending these frames.
- Input/textarea focus state is border 1→2px only (no padding compensation, so content shifts ~1px) - matches design.md's documented Input component exactly, rather than inventing a layout-stable compensation Figma itself doesn't use.
- Added `--text-h5: 20px` - the dialog title is 24px on desktop but 20px on mobile, and 20px isn't on design.md's existing scale (12/14/16/24/28/32/40/52); same pattern as the earlier `--radius-prompt` addition for a real Figma value the documented scale didn't cover.
- "+ Projet" (in the already-built Liste des projets) now opens this dialog - necessary wiring to reach the screen at all, same precedent as wiring the chat composer into the previously-built Projet frame.
- On save: the new project is prepended to the list (shows first, not appended) - matches SPEC.md's own script, where "Voyage à Copenhague" is visibly present immediately after creation without implying the user must scroll.
- Save is disabled until the name is non-empty (no error message, just a disabled button) - SPEC.md's "happy path only, no validation errors" decision already ruled out red-text/error states; this prevents a degenerate empty-named project without adding one.
- Escape, the "×" button, "Annuler", and clicking the overlay all close without creating a project, and reopening always starts blank - standard modal behavior, verified by script rather than assumed.
- Source preview dialog reuses `components/ui/dialog.tsx` as-is (same header/title/close pattern as Create Project) - Figma's own structure for this Popover is identical (Titecontainer + Slot + Buttons), just sized 358/874px instead of 366/576px and with one button instead of two.
